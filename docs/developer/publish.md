# 发布

这里有两种部署形态, 可以设计方面可以讨论一下:

## 工具类库模式

这种比较好理解, 就是线下开发, 所有的输出都是工程内容, 实际运行是一个 starter 拉起, 整体模式跟目前开发一直.
此模式下, 集成平台提供的是一套可扩展的组件模式和基础框架类库, 外加常用的官方组件.
好处是符合开发流程, 应用的生命周期管理也完全可以依赖 Dice, 以一个服务来部署.
缺点来说, 就不太像一个集成产品了, 改动也需要走标准的发布流程.

## 平台模式

平台模式则指集成平台有一个控制台, 允许在线完成集成配置, 完成后通过在线发布的方式, 自动完成编译部署等, 连同监控告警等功能一并提供.
这种模式好处是类似 IPaaS 的形式, 通过不断丰富组件库, 可以对外输出为一个集成产品, 使用方面在线编辑/在线部署的方式也更加简单, 半脱离开发态.
问题点在于要管理部署, 这部分目前只能对接 Dice 了, 而且对于资源的使用情况, 是否扩容等, 可能都要留口或者自动处理掉.
另外就是对外暴露服务的方式了, 例如域名, MQ 或者 Dubbo 所使用的中间件等, 都需要依托于 Dice.

从接收到的信息来说, 貌似更期望以此种模式处理.
